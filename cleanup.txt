1. SECURITY AND PRIVACY
=====================================================================================

S1  HIGH  Next.js 14.2.35 has known security advisories (1 critical, plus postcss high)
    Where:  frontend/package.json ("next": "14.2.35")
    Why:    npm audit reports a critical advisory (denial of service via the image optimizer
            and others) and high-severity postcss issues. No 14.x release fixes them.
    Change: upgrade to Next.js 16.4.1 or later. This needs React 19 and some code changes
            (route params become async). Test the whole site afterwards (working.txt lists
            every function).
    Effort: medium-large

S2  HIGH  Firebase 10.14.1 pulls in vulnerable packages (@grpc/grpc-js high, undici high,
          @firebase/firestore high, 8 moderate)
    Where:  frontend/package.json ("firebase": "^10.14.1")
    Change: upgrade to firebase 13; re-test Google sign-in. Then remove the direct "undici" and
            "idb" dependencies if the build passes without them (they were added as a workaround).
    Effort: medium

S3  HIGH  Firestore lets anyone list the "supporters" collection without signing in
    Where:  Firebase console > Firestore > Rules; written by frontend/src/lib/firebase.ts:204
            (saveSupporterToFirestore)
    Why:    A test request with no sign-in got HTTP 200 for the list of supporters. It is empty
            today, but any record saved there (name, phone, address) would be public.
            The app writes to it without sending a sign-in token, so the rules either reject
            every write (feature broken) or must allow anyone to write (worse).
    Change: the new Postgres database now stores profiles, so the simplest fix is to remove
            saveSupporterToFirestore and its 4 callers and lock the rules:
              match /supporters/{uid} { allow read, write: if request.auth.uid == uid; }
            If you need the Firestore copy, write it with the Firestore SDK as the signed-in
            user instead of the REST URL.
    Effort: small

S4  HIGH  Firebase authorised domains include "vercel.app" and other projects' domains
    Where:  Firebase console > Authentication > Settings > Authorised domains
            Current: localhost, ai-foundation-firebase.firebaseapp.com, ...web.app, 127.0.0.1,
            aifoundationweb.vercel.app, vercel.app, g-class-builder.vercel.app,
            aifoundation.net.au, pro-lms-c44d1.firebaseapp.com
    Why:    "vercel.app" allows ANY website hosted on Vercel to run your Google sign-in, which
            makes convincing phishing pages possible.
    Change: remove "vercel.app"; add only this site's exact production domain. Remove domains of
            other projects unless they really share this Firebase project.
    Effort: small

S5  HIGH  ImgBB API key is hard-coded in browser code and committed to git (twice)
    Where:  frontend/src/lib/imgbb.ts:7 and frontend/src/lib/medicalData.ts:13
    Why:    Anyone can read it and upload to (or fill) your ImgBB account. The server now has its
            own copy in IMGBB_API_KEY, and neither browser copy is used.
    Change: delete both constants (see D2, D3), then create a new key at imgbb.com and put it
            only in IMGBB_API_KEY (Vercel settings / .env.local). Old key stays in git history,
            so rotating it is what actually closes the hole.
    Effort: small

S6  HIGH  Uploaded scans are public on ImgBB, and only hidden photo data is removed
    Where:  frontend/src/server/imgbb.ts (your decision this session was to keep ImgBB)
    Why:    Anyone with an image link can view it. Removing EXIF data does not remove patient
            names or IDs burned into the image pixels, which is common on X-rays and scans.
    Change: at minimum, make uploaders confirm the image is de-identified (there is an
            "is_anonymized" field; require it to be true before upload). Longer term, a
            private store (Firebase Storage / Vercel Blob) with expiring links.
    Effort: small (confirmation) / medium (private store)

S7  MEDIUM  Type checking and lint are switched off for builds
    Where:  frontend/next.config.mjs (typescript.ignoreBuildErrors, eslint.ignoreDuringBuilds)
    Why:    Errors ship to production silently. Type checking now passes with 0 errors.
    Change: remove ignoreBuildErrors now; remove ignoreDuringBuilds after the lint list (D5).
    Effort: small

S8  MEDIUM  A fake type file switches off type checking for all Firebase code
    Where:  frontend/src/types/firebase.d.ts (35 lint warnings)
    Why:    It declares firebase/app, firebase/auth and firebase/firestore as "any", hiding real
            mistakes. This is how page.tsx read a field that didn't exist (fixed this session).
    Change: delete the file; the real Firebase types are installed. Fix any errors that appear.
    Effort: small

S9  MEDIUM  Personal details are cached in browser storage
    Where:  "tmh_user" in localStorage: frontend/src/lib/firebase.ts, src/app/page.tsx,
            src/components/SupporterProfileModal.tsx
    Why:    Phone, address and comments stay in the browser (readable by any script on the page,
            and by the next person on a shared computer until Log Out).
    Change: cache only id, name and role; load the rest from /api/auth/me when the profile opens.
    Effort: small

S10 MEDIUM  Exact GPS position is sent to OpenStreetMap
    Where:  frontend/src/lib/geoSettings.ts:117
    Why:    data-contracts.md says coordinates are rounded to 2 decimal places (~1 km);
            the code sends full precision.
    Change: round lat/lon to 2 decimals before building the URL.
    Effort: small

S11 LOW  Stripe secret (test) key visible in the Stripe MCP command line
    Where:  Not in this repo: Antigravity starts "@stripe/mcp --api-key=sk_test_..." and the key
            shows in the process list.
    Why:    Any program on the PC can read it. Harmless for a test key; never do this with the
            live key.
    Change: pass the key to the MCP through an environment variable instead.
    Effort: small

S12 LOW  backend/.env holds secrets for the retired Python backend
    Change: keep GEMINI_API_KEY / IMGBB_API_KEY / STRIPE_* in frontend/.env.local and Vercel,
            then delete backend/ with D1.
    Effort: small

C1  HIGH  The 6 "curated" research articles and 6 news items are invented
    Where:  frontend/src/lib/medicalData.ts ("academic" and "news" in each scan)
    Why:    Every PubMed ID, PMC ID and DOI was checked: none matches its article. Links open
            unrelated papers (e.g. glaucoma knowledge in Taiwan, pig carcass quality, soil
            carbon). Some news is credited to real bodies ("Queensland Health Newsroom",
            "Australian Journal of Rural Health"). On a medical education site this misleads
            students and risks the organisation's credibility.
    Change: replace with verified references (title, authors, journal, year, PMID and abstract
            taken from PubMed), or clearly label them "illustrative example". Same for news.
    Effort: medium

            by Stripe".
